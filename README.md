# 云原生构建 CNB · magpie 供应商插件

把一个 **CNB（cnb.cool）** 账号变成 magpie 里的一个供应商：点一次「浏览器网页登录」，
插件开的受控窗口里登一次、确认一次授权，当月 AI Credit 与认证徽章上卡片的同时，
**CNBSESSION**（跑模型用的网页登录态）也一起收下了 —— DeepSeek / GLM / Kimi 当场能跑。
不想开第二个窗口也行：设备码登录拿访问令牌，再把浏览器里的 CNBSESSION 粘进来（或指向自建中继）。

```
配额      **按月**发 AI Credit（每月 1 日 UTC 重置）· 免费档 500 / 月，完成入门任务后 1,166 / 月
可选模型  8 个（DeepSeek V4.1 / GLM 5.3 / Kimi K3 / Hunyuan 4 等）
登录方式  4 种（浏览器网页登录 / 浏览器设备码 / 本机 cnb-cli / 粘贴凭证）
跑模型要  一条 CNBSESSION（网页登录态）或一条自建 relay —— 「浏览器网页登录」一趟就给你
工具调用  ✗ **不支持** · Cookie 通道结构性拒绝，只有 relay 通道能带 tools
```

> ⚠ **不能调用工具 —— 这一条决定它能不能进 agent。** CNB 的网页 AI 端点结构性拒绝 `tools`
> （上游回 `403 Agent calls are not allowed`），插件在发出去之前就拦住并返回 `501 not_implemented`。
> 而 agent 客户端每个请求都带 `tools` —— 用它必然失败，且那个 501 会被 magpie 当成可重试的失败，
> 把这个账号冷却一轮（界面上就是「失败 · N 秒后恢复」反复出现）。
>
> 纯聊天照常可用：写代码、读长文、解释报错、看图（`glm-5.3-flash-vision`）。
> 要工具只能 `transport: "relay"` 指向一个**自己搭的** OpenAI 兼容中继 —— 那不是 magpie 本身
> （填本机网关会成环），中继后面得有真支持 tools 的上游。

> **额度是按月的，没有「每日额度」这一说。** CNB 发的是 AI Credit（当月），每月 1 日 UTC 重置；
> 免费档 500 credits/月，完成 hello-cnb 入门任务后到 1,166 credits/月（500 免费 + 666 认证/特权）。
> 数字来自参考实现对真实账号的读卡记录，**按组织发放**，最终以你 `/{org}/-/charge/quota` 的读数为准。
> 一次对话消耗多少 credit，上游响应里不报（只有 token 数），所以「一天能聊几句」没有官方换算。

> ⚠ **登录 ≠ 能聊天 —— 但有一条路能一次搞定。** 设备码登录、读本机 `cnb-cli`、粘贴访问令牌，
> 这三条路拿到的都是**访问令牌（PAT）**，而 CNB 的 AI 端点只吃网页登录态：拿 PAT 去打上游
> 一律回 `403 [NO_RIGHT] OpenAPI only allowed in pipeline`。
> 所以额度条会立刻有数，但「AI 通道」那一行会明确写着还差什么。
>
> 想一次拿齐（额度 + 通道）就选 **「浏览器网页登录」**：插件开一个受控浏览器窗口，
> 你在窗口里登录 cnb.cool 再点一次「确认授权」，两条凭据一起收下；账号还没有组织的话，
> 没有组织也不影响跑模型 —— AI 端点用公开仓库就够了；只是额度那一行要等你有组织才读得出。

## 一次到位，或者两步走

**省事的那条：登录时选「浏览器网页登录」。** 插件开一个受控浏览器窗口
（一次性 profile，不碰你日常浏览器的数据），你在里面登录 cnb.cool、点一次「确认授权」，
它同时收下**网页登录态（跑模型）**与**访问令牌（查额度）**。没有组织也能跑模型（见下）。
一次登录，额度和通道都有 —— 卡片上的两行同时亮。

**想分开也行**（有时候你就是不想再开一个浏览器窗口）：

1. **登录**（剩下三种任选）→ 拿到访问令牌：额度、徽章、账号名全都出来了。
2. **补一条通道**（任选其一）→ 才能真跑模型：
   - **粘 CNBSESSION**：浏览器登录 cnb.cool → F12 → Application → Cookies →
     复制 `CNBSESSION` 的值 → 在「粘贴访问令牌」那一栏粘进去（插件会在运行时认出这是会话而不是令牌）。
   - **配 relay**：选项里 `transport: "relay"` + `relay.url` 指向一个 OpenAI 兼容中继。
     **要工具调用只能走这条** —— CNB 网页端点结构性拒绝 tools。

## 功能

- **浏览器网页登录：一趟拿齐额度 + 通道**：插件开一个受控浏览器窗口（一次性 profile，
  不读也不写你日常浏览器的数据），你在窗口里登录 cnb.cool 点一次「确认授权」，
  CNBSESSION（跑模型）与访问令牌（查额度）一起收下。要本机装有 Chromium 内核浏览器
  （Chrome / Edge / 360 / QQ / Brave 等）。
- **没组织也能跑模型**：AI 端点不要求仓库属于你自己的组织 —— 一个公开仓库（`cnb/docs`）就够，
  实测回 200 + 正常 SSE。所以「还没有组织」只影响额度那一行，不影响 agent 能不能用。
  想要额度就去 `cnb.cool/new/groups` 建一个（**一个根组织一年只能建 1 个，删掉不退还**），
  所以插件默认不替你建；要自动建就在插件选项里显式写 `"createOrg": true`。
- **要跑模型不用建任何东西**：默认仓库路径是 `cnb/docs`，也可以用自己的：
  选项里填 `repo`（`org/repo` 形式）或者 `repoName`（默认 `code`，会拼成 `{org}/code`）。
- **一键登录，可以加多个账号**：走 CNB 自己的 OAuth 设备码授权，浏览器里确认一次就行；
  全程不读也不写你本机的任何凭证文件，所以登几个账号都不会互相覆盖。
- **不想点浏览器也行**：装过 `cnb-cli` 的话，直接读它的登录态（过期自动续期）；
  手头已经有访问令牌或浏览器 Cookie 的话，粘一个进去也认。
- **当月 Credit 直接上卡片**：已用 / 总额 / 特权额度 / 重置时间一次显示，
  读数拿不到时明确说原因 —— 不伪造 0%，也不拿 `0 / 0` 冒充「已用光」。
- **认证徽章**：天才程序员、高校学生 / 老师 / 校友 / 职工、内测玩家 / 开服玩家、TDP，
  从账号自己的 `identity_providers` 读，读不到时用特权额度说明兜底。
- **两条 AI 通道**：CNBSESSION 直连 CNB 网页端点（不用 API key），或指向你自己的
  OpenAI 兼容中继（**要工具调用走这条**）。
- **诚实的工具能力标注**：Cookie 通道下模型会标成不能调工具 —— 因为上游确实会拒，
  与其让 agent 发出去吃一个 403，不如提前说清。
- **令牌自动续期，且是串行的**：同一个 `refresh_token` 不会并发换两次
  （换两次 = 账号被踢下线，这是这类插件最常见的坑）。

## 模型

CNB 的可选模型是固定的 8 个（它没有公开的 `/models` 端点）：

| 模型 | 上下文 | 最大输出 | 说明 |
|---|---|---|---|
| `deepseek-v4.1-flash` | 1M | 64K | 默认 |
| `deepseek-v4-flash` | 1M | 64K | |
| `glm-5.3` | 1M | 64K | 带思考档 |
| `glm-5.3-flash` | 1M | 128K | 带思考档 |
| `glm-5.3-flash-vision` | 1M | 32K | **能收图** |
| `glm-5.2` | 200K | 32K | |
| `kimi-k3` | 1M | 32K | 带思考档 |
| `hy4-preview` | 1M | 64K | 带思考档 |

在 magpie 里它们显示成 `cnb/deepseek-v4.1-flash` 这样的名字。

> Cookie 通道下这 **8 个模型全部标成 `tool_call: false`** —— 不是漏标，是上游真的拒。
> 别把它们放进会带 `tools` 的路由组：组是手工配的静态列表，magpie 不会因为这条声明
> 把成员筛掉，于是请求照样派过去、然后吃一个 501。

## 签到

CNB **没有**「每日签到」接口 —— 免费 AI Credit 是按月发的（每月 1 日 UTC 重置），
所以这个插件的签到结果是 `inactive`（不假装签了）。

如果你的领取流程是自建的（比如某个包装端点），在插件选项里填 `claim.url`，签到就会去打它。

## 安装

在 magpie 里：**插件 → 添加插件 → 填仓库地址**。

```bash
magpie plugin add github:MYCF711/magpie-cnb-auth
magpie plugin login cnb      # 想一次拿到「额度 + 通道」就选「浏览器网页登录」
magpie quota                 # 看当月 Credit 与徽章
magpie provider test cnb     # 发一个很小的请求验证通道
```

装完在应用的 **供应商** 页能看到 `云原生构建 CNB` 这一行，登录后卡片上就有额度和徽章。

### 选项（可选，全部有默认值）

```json
{
  "org": "",              // 组织 slug，留空自动探测
  "repo": "",             // 仓库路径（AI 通道要用），留空自动取第一个可见仓库
  "transport": "auto",    // auto | cookie | relay
  "relay": { "url": "", "key": "" },
  "claim": { "url": "", "method": "POST", "body": "{}" },
  "repoName": "code"
}
```

多数人不需要填任何一项：登录时会自动探测组织与仓库。

## 常见问题

**1. 为什么点完登录，模型能聊了但额度条是空的？**
额度查的是 `api.cnb.cool`，它只认**访问令牌**；如果你是用「粘贴 CNBSESSION」登录的，
或者「浏览器网页登录」时窗口里的「确认授权」没点完（只拿到网页登录态），
那条凭据跑不了额度接口。到 <https://cnb.cool/profile/token> 生成一个访问令牌补进来即可，
或者重登一次「浏览器网页登录」并把「确认授权」点完。

**2. 为什么模型调不了工具？**
CNB 的网页 AI 端点结构性拒绝工具调用（上游回 `403 Agent calls are not allowed`），
插件的做法是在出网之前就返回 `501 not_implemented` —— 不透传那个 403，因为 403 在 magpie
的语义里会通向「登录失效」，把一个好好的账号摘掉。

**这条对 agent 是致命的**：agent 每个请求都带 `tools`，所以凡是会自己读文件、跑命令的客户端，
用这个供应商都会失败；而且 501 属于「可重试」，magpie 会换号、同时把这个账号冷却，
卡片上就显示成「失败 · N 秒后恢复」反复刷。
正确做法是**别把 `cnb/…` 放进带 tools 的路由组**，它只在纯聊天场景有用。

要工具就把 `transport` 设成 `relay`，指向一个**自己搭的** OpenAI 兼容中继；
Cookie 通道本身做不到。注意 relay 填的不是 magpie 自己的地址 —— 那会成环。

**3. 报「缺少仓库路径」怎么办？**
CNB 的 AI 端点挂在 `/{org}/{repo}/-/ai/chat/completions` 下，必须有仓库。
登录时会自动取你组织下第一个可见仓库；取不到就在选项里手填 `org` 与 `repo`。

**4. 报「上游返回了 HTML」是什么意思？**
通常是仓库路径不对（那个路径不存在），或者登录态过期了。它**不是**模型坏了 ——
所以插件没有把它报成「模型不存在」，否则 magpie 会把这条模型搁置。

**5. 想加第二个账号？**
用「浏览器授权登录」，可以登任意多个。「用本机 cnb-cli 的凭证」只能读到那一个账号 ——
`~/.cnb/token` 只由终端的 `cnb login` 写，在浏览器里换账号不会更新它。

**6. `deepseek-v4.1-flash` 之外的模型好像都答得差不多？**
有作者观察到 CNB 上游对部分模型 id 会静默回退到主模型。这是服务端行为，
插件不做别名改写（`model` 原样透传）—— 硬写一张映射表只会让你以为切了模型。

**7. 卡片说「这个 CNB 账号还没有组织」？**
CNB 的 AI Credit 按**组织**发放，AI 端点也挂在 `/{org}/{repo}/-/ai/...` 下，
所以刚注册、还没建组织的账号既没有额度可读、也没有通道可用（实测：这种账号的
`/user/groups` 就是空数组）。到 <https://cnb.cool/new/groups> 建一个组织（或让管理员把你加进去），
再回来刷新这张卡就行。已经有组织却还显示这条，就在插件选项里直接填 `org`。

**8. 卡片上的账号名是我填的昵称吗？**
是。CNB 给新账号自动生成的 `username` 长得像 `cnb.dI2DzHg0QHA`，那不是名字 ——
插件取的是 `nickname`；昵称也取不到时**留空**，由 magpie 回退成供应商名，而不是显示一串 ID。

**9. 点「浏览器网页登录」之后什么都没发生？**
三种可能，按顺序排：

1. **本机没有 Chromium 内核浏览器** —— 这条登录路会明说「没找到 Chromium 内核浏览器」，
   并列出该装什么。装好 Chrome / Edge 任意一个再来。
2. **窗口被提前关掉了** —— 插件要等两件事都完成才收工：窗口里的 cookie 已经抓到、
   以及你点了页面上的「确认授权」。关早了就只能拿到一半（cookie 那一半还可能拿不到），
   卡片上会照实说缺什么。
3. **窗口还在跑** —— 它最多等 5 分钟；「确认授权」那一半的轮询预算跟设备码自己的寿命
   （≈10 分钟）对齐，所以**不会出现「窗口还开着、轮询已经放弃」**。期间别关窗，让它自己收工。

**10. 想让插件自动建组织？**
**先说结论：不为跑模型建组织。** AI 端点用公开仓库就能调（`cnb/docs`，实测 200 + 正常 SSE），
组织只决定额度能不能读出来。而组织有硬限制：**一个根组织一年只能建 1 个，删掉不退还**
（实测 `429 The root organization has reached its yearly creation limit`）。

所以默认不建。真要开：插件选项里写 `{"createOrg": true}`，它会在「浏览器网页登录」那一次里试一次，
失败不重试、也不会把登录判失败（状态码写进卡片）。手动建就在 <https://cnb.cool/new/groups>。

> **还没被验证的那一步**：插件开的是一次性 profile，里面没有登录态，所以
> 「人在窗口里登录一次 → 插件拿到 CNBSESSION」这一段**没有走过**。
> 已经证明的是：窗口能开、CDP 能读 Cookie、以及**拿到 Cookie 之后整条链路跑得通**
> （用另一个本来就登录着的浏览器的会话验的）。

接口本身是验过的：`POST https://cnb.cool/groups`（网页侧，不是 `api.cnb.cool` —— 那个网关不认 Cookie）
配上 `csrftoken` 头会回 `201 Created`；slug 规则也来自上游原话：长度 3–50、首尾不能是特殊字符。
